# ADR-0001：音源获取采用「多路叠加责任链」

- 状态：**已接受**（2026 立项）
- 相关：`docs/PLAN.md` §1.2.1、§2.5

## 背景

网易云官方不提供开放的播放地址保证：
- 未登录 / 非 VIP 调用 `/song/url/v1`，大量歌曲返回 `null` 或 **30 秒试听**；
- 非大陆 IP 会命中地域限制，大批歌曲不可用；
- 播放地址有效期仅分钟级，过期 403。

产品目标是「音源数量多 + 尽量无损」，单一来源无法满足。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 只用官方接口 | 完全合规、稳定 | 覆盖窄、无 VIP 无无损 | ❌ 不满足需求 |
| B. 只接一个第三方聚合 API | 接入最快 | 单点依赖，服务挂即全挂；隐私不可控 | ❌ 脆弱 |
| C. 内嵌 UNM **作为系统代理 + 改 hosts** | 能同时解锁官方客户端 | 需 MITM 自签证书、污染系统网络配置、影响其他程序 | ❌ 侵入性过高 |
| D. **多路叠加责任链**：官方 ⊕ UNM(库调用) ⊕ LX 插件，全部经真实音质校验 | 覆盖率与质量最高；单源失效可回落；插件生态复用现成脚本；无系统侵入 | 实现复杂度最高；有灰色合规风险；需要沙箱 | ✅ **采纳** |

## 决策

1. 抽象 `MusicSource` 契约（`packages/source-core`），`packages/resolver` 以**责任链**按 `L0 官方 → L1 UNM → L2 聚合(默认关) → L3 LX插件 → L4 本地` 依次尝试。
2. **UNM 作为 npm 依赖库进程内调用** `match(songId, sources)`，不使用系统代理、不改 hosts、不装证书。
3. **插件格式直接兼容 LX Music 自定义源协议**，复用社区生态，而不是自造格式。
4. 任何来源都必须通过 `QualityProbe`（HTTP `Range: bytes=0-3` 嗅探 `fLaC`/`ID3`/`ftyp`/`OggS` + 码率估算）后才可用于展示与下载，**UI 徽标只显示实测结果**。
5. **安全红线**：登录 cookie / `MUSIC_U` 仅用于 L0，绝不传给任何第三方源。
6. 第三方源**默认关闭**，首次启用需二次确认并告知风险。

## 后果

**正面**
- 覆盖率与音质上限同时最大化：VIP 场景走官方真无损，变灰歌走多平台 FLAC。
- 任一音源失效不影响整体可用性，符合「长期可维护」目标。
- 插件生态免开发成本，用户可自行扩充音源。

**负面 / 代价**
- `resolver` + 沙箱 + 音质探测是额外工程量（见 M2.5、任务组 H）。
- 第三方音源存在版权与合规风险，且随平台反爬随时失效。
- 需要音源健康检查与自动降权机制，否则用户会遇到「莫名播不了」。

## 复审触发条件

- 上游 UNM 长期停更或 `match()` 接口不可用 → 评估自建匹配器或替换实现。
- LX 插件协议发生不兼容变更 → 锁定兼容版本或增加适配层。
- 官方开放正式授权接口 → 优先回归 L0，收缩第三方依赖。

## 实现现状（M2.5 收口）

按本文落地，并把含糊处钉死成下面这些实现细节（`docs/PLAN.md` §9 有实测记录）：

| 决策 | 落地位置 | 实现时具体化成什么 |
|---|---|---|
| 1 责任链 | `packages/source-core`（契约）、`packages/resolver`（链 + 健康登记 + 探针） | 实际链序 `L0 官方 → L1 UNM → L3 LX → L4 本地`；**L2 聚合留位未实现**，链上没有中间聚合源。`LocalSource` 永远最后——用户硬盘上的同名文件不该抢在官方源前面 |
| 2 UNM 作为库 | `packages/source-unm` | `createRequire` **惰性**加载（`ENABLE_FLAC` / `LOG_LEVEL` 必须在 require 之前设好），只调 `match()`，不起服务；平台顺序可配，默认 `['bodian','kugou','migu']`——实测只有 bodian 出货（3.8~5.9s，`br=999000` 即 FLAC），kugou 114ms 就 `No audioData!`、migu 2.1s 无货，所以 `timeoutMs = 20s` 且不追求「多平台更快」；结果带 TTL + 负缓存（负缓存从**失败时刻**起算） |
| 3 LX 协议兼容 | `packages/source-lx` | 沙箱形式从「Node `vm` 或 `utilityProcess`」改成 **`ELECTRON_RUN_AS_NODE` 独立子进程 + 该进程内 `node:vm` 白名单上下文**：主进程内的 vm 挡不住 CPU 死循环，也挡不住脚本顺着宿主对象摸到 `process`。白名单里**没有** `require` / `process` / `fs`，`lx.request` 经 IPC 回主进程转发（可审计、可限流）。导入只接受文本/文件，不接受 URL |
| 4 只认实测 | `packages/resolver/src/probe.ts` + `qualityFromProbe` | 取 `Range: bytes=0-65535`（必须够到 FLAC 的 STREAMINFO 才能读真实采样率）；实测与来源自称不一致时 `ResolvedAudio` 同时带 `claimedQuality`，UI 显示「标称 X，实测只到 Y」。本地文件的探针直接读盘 64KB，不走 HTTP |
| 5 cookie 红线 | `MusicSource.needsCookie` + `Services.publish()` | 只有 L0 的 `needsCookie` 为 `true`；`upstreamHeaders` 与 `localPath` 在 `publish()` 里被 `delete` 掉，渲染进程只拿到本机代理的不透明地址；第三方源的回源请求头独立，**不能套用网易的 `Referer`** |
| 6 默认关闭 | `Settings.enableThirdPartySources` + `thirdPartyAcknowledged` | 两个字段是**与**关系，默认都为 `false`；首次勾选弹二次确认，四条风险明写「cookie 不会交给第三方」。⚠️ `docs/PLAN.md` §8 第 11 条原先写的「默认开启」与本文冲突，已按本文更正 |

**验收证据**：`PI_SMOKE_SOURCES=1` 冒烟 exit 0（变灰歌《晴天 (钢琴版)》→ `unm` 匹配到 `flac 48000Hz`、徽标是实测值、关掉第三方开关后 attempts 只剩 `[wy]`）；`pnpm typecheck` 14/14；单测 119 例全绿（`quality` / `health` / `chain` / `source-unm` / `source-lx` / `source-official`，另补 `source-local`）。

**新增的复审触发条件**：某个平台可能长期无货（本机就是 kugou / migu 全灭）——平台顺序必须保持可配，不能把「谁快用谁」硬编码成常量。
