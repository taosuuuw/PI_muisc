# ADR-0002：本地存储采用零原生依赖的 JSON 文件存储

- 状态：**已接受**（2026 立项）
- 相关：`docs/PLAN.md` §2.6、§1.3

## 背景

需求新增硬约束：**应用要在大部分环境下都能运行**，且用户不做任何环境准备（不装 Node、不装编译工具链、不要管理员权限）。

原计划用 `better-sqlite3` 存下载记录、播放历史与各类缓存。它是**原生模块（native addon）**，二进制必须同时匹配三个要素：操作系统、CPU 架构、以及 Electron 的 ABI 版本。

## 备选方案

| 方案 | 跨环境可运行性 | 能力 | 结论 |
|---|---|---|---|
| A. `better-sqlite3` | ❌ 差：需匹配 ABI；匹配不上要现场 `node-gyp` 编译，用户机上常无 VS Build Tools / Xcode CLT | 强（事务、索引、SQL） | ❌ 与硬约束冲突 |
| B. `node:sqlite`（Node 22.5+ 内置） | ⚠️ 中：取决于 Electron 内置的 Node 版本，且仍是实验特性 | 中 | ⚠️ 暂不采用，留作观察 |
| C. `sql.js`（WASM） | ✅ 好：无原生编译 | 中：内存数据库，需自行落盘，大库全量序列化开销大 | ⚠️ 备选 |
| D. **JSON 文件存储 + `StorageDriver` 抽象** | ✅ 最好：纯 JS，任何环境直接跑 | 够用：本项目数据量级（万级记录）完全够，配合内存索引可满足需求 | ✅ **采纳** |

## 决策

1. 定义 `StorageDriver` 接口（`get / set / delete / query / transaction / flush`），业务层只依赖接口。
2. 默认实现 `JsonFileDriver`：**纯 JS、零原生依赖**，写入走「临时文件 + 原子重命名」，避免断电/崩溃损坏数据；内存中保留索引，按需持久化（去抖 500ms）。
3. 数据按域分文件（`history.json` / `downloads.json` / `cache/*.json` / `settings.json`），避免单文件过大与写放大。
4. 全部数据存放于 Electron `app.getPath('userData')`，不写系统目录，不需要管理员权限。
5. **保留升级路径**：将来若要 SQLite，只需新增一个 `SqliteDriver` 实现并在启动时探测，业务层零改动。

## 后果

**正面**
- 彻底消除「装不上 / 编译失败 / ABI 不匹配」这一整类跨环境故障。
- 打包体积更小，无需 `electron-rebuild`，CI 三平台构建更简单。
- 数据文件是人类可读的 JSON，便于用户备份与排障。

**负面 / 代价**
- 复杂查询（多条件、聚合、全文检索）需在内存索引上手工实现。
- 数据量增长到十万级以上时，全量持久化会成为性能瓶颈。
- 无事务隔离与并发写入保护（本项目为单进程单窗口，风险可控）。

## 复审触发条件

- 单一数据文件超过约 50MB，或启动加载耗时超过 300ms。
- 需要跨表聚合/全文检索等 JSON 索引难以支撑的查询。
- `node:sqlite` 在 Electron 内置 Node 上转为稳定特性。
